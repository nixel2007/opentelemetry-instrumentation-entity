# ОтелИнструментированиеХранилища

Инструментирование слоя хранилищ сущностей: оборачивает хранилище в декоратор, который на каждый вызов метода создает спан и пишет длительность вызова в гистограмму. Аналог `spring.data.repository.invocations` в Spring Data.

Операции менеджера и запросы к СУБД, которые выполняет метод хранилища, становятся дочерними спанами — при условии, что на источнике данных зарегистрирован [`ОтелНаблюдательИсточникаДанных`](ОтелНаблюдательИсточникаДанных.md).

## Создание

```bsl
Инструментирование = Новый ОтелИнструментированиеХранилища(Трассировщик, Метр);
```

| Параметр | Тип | Назначение |
| --- | --- | --- |
| `ОтелТрассировщик` | `ОтелТрассировщик` | Трассировщик для спанов вызовов |
| `ОтелМетр` | `ОтелМетр` | Метр для гистограммы вызовов |

## Обернуть

```bsl
Хранилище = Инструментирование.Обернуть(Хранилище, "ХранилищеФизическиеЛица");
```

| Параметр | Тип | Назначение |
| --- | --- | --- |
| `Хранилище` | Произвольный | Хранилище сущностей: типизированное из entity либо собственное |
| `ИмяХранилища` | `Строка` | Имя хранилища в спанах и атрибуте `entity.repository` |

Возвращает обертку с перехватчиками. Если оборачивать нечего, возвращается исходный объект — подменять его пустой оберткой незачем.

Оборачиваются экспортные методы фактического объекта, кроме тех, что не ходят в базу данных: `ПолучитьОбъектМодели`, `ПолучитьПулСущностей`, `СоздатьЭлемент`, `Закрыть`. Методы берутся с самого объекта, а не из его типа: у собственного хранилища не видно методов, унаследованных от `ХранилищеСущностей`, а у типизированного хранилища entity в типе нет ни одного.

Если собственное хранилище делегирует вызов родителю и родитель обернут тоже, у делегированного вызова получается два вложенных спана — свой и родительский.

## Сигналы

| Сигнал | Имя | Атрибуты |
| --- | --- | --- |
| Спан INTERNAL | `{ИмяХранилища}.{ИмяМетода}` | `code.function.name`, `code.namespace`, `error.type` |
| Гистограмма, с | `entity.repository.invocations` | `entity.repository`, `code.function.name`, `entity.repository.state`: `success`, `error`, `error.type` |

Исключение метода записывается событием спана, спан получает статус ошибки и атрибут `error.type` — имя модуля, в котором исключение возникло, либо `RuntimeError`, если модуль неизвестен. Точка гистограммы в этом случае получает `entity.repository.state` со значением `error`.

Границы бакетов гистограммы берутся из семантических соглашений для клиентов баз данных, длительность — в секундах.

## Пример

```bsl
#Использовать entity
#Использовать opentelemetry
#Использовать opentelemetry-instrumentation-entity

Сдк = ОтелАвтоконфигурация.Инициализировать();

Источник = Новый ИсточникДанных("Основной", Тип("КоннекторPostgreSQL"), СтрокаСоединения);
Источник.ДобавитьНаблюдателя(Новый ОтелНаблюдательИсточникаДанных(
    Сдк.ПолучитьТрассировщик("entity"),
    Сдк.ПолучитьМетр("entity")
));

МенеджерСущностей = Новый МенеджерСущностей(Источник);
МенеджерСущностей.ДобавитьКлассВМодель(Тип("ФизическоеЛицо"));
МенеджерСущностей.Инициализировать();

Инструментирование = Новый ОтелИнструментированиеХранилища(
    Сдк.ПолучитьТрассировщик("entity"),
    Сдк.ПолучитьМетр("entity")
);

Хранилище = Инструментирование.Обернуть(
    МенеджерСущностей.ПолучитьХранилищеСущностей(Тип("ФизическоеЛицо")),
    "ХранилищеФизическиеЛица"
);

// Спан ХранилищеФизическиеЛица.Получить, внутри - спаны операции и запроса
Лица = Хранилище.Получить();
```
